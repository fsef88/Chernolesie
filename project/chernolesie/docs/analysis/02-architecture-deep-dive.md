# Глубокий разбор архитектуры Чёрнолесья

## 1. Модель исполнения (самое важное)

Игра **не использует модульную систему**. Все 91 файл собираются в **три больших `<script>`** блока.

### Почему так сделано

```js
// Пример зависимости, которая требует правильного порядка
// core/input.js:39
document.getElementById('tbtnPause').addEventListener('click', togglePause);

// togglePause объявлена в ui/overlays.js (загружается позже)
```

**Вывод**: Порядок файлов в `tools/manifest.mjs` = порядок исполнения = **критически важен**.

## 2. Система Spatial Hash (отличная оптимизация)

**Файл**: `core/spatial-hash.js`

### До v6.3 (плохо)
- `Map<string>` с ключами `"cx,cy"`
- Каждый кадр создавалось 4300+ строк при капе 72 врага
- Постоянные аллокации → GC → просадки FPS

### После v6.3 (хорошо)
```js
const GRID_N = Math.ceil(WORLD/CELL) + 2;
const gridArr = new Array(GRID_N * GRID_N);  // плоский массив
let _gridUsed = [];                          // только использованные ячейки

function buildGrid() {
  for (let i = 0; i < _gridUsed.length; i++) {
    gridArr[_gridUsed[i]].length = 0;        // переиспользование
  }
  _gridUsed.length = 0;
  // ...
}
```

**Результат**: ноль аллокаций в устоявшемся состоянии.

## 3. Система разделения врагов (v7.8)

**Файл**: `core/loop.js`

### Проблема до v7.8
```js
const _sepGrid = new Map();
// Ячейка заводилась на каждые 48px пути и НИКОГДА не удалялась
// 20 000 px пути → 10 252 ячейки → 44 мс/сек на десктопе
```

### Решение v7.8
```js
const _sepFree = [];  // пул пустых массивов

function _sepClear() {
  for (const ent of _sepGrid) {
    if (ent[1].length === 0) {
      _sepGrid.delete(ent[0]);
      if (_sepFree.length < 512) _sepFree.push(ent[1]);
    } else {
      ent[1].length = 0;
    }
  }
}
```

**Результат**: размер сетки держится по числу **занятых** ячеек.

## 5. Система синергий (лучшая часть)

**Файл**: `data/cards.js`

### Уровни билда
1. **Уровень 1** — Оружие / Аура (карты)
2. **Уровень 2** — Эволюция (сундук, 5 ур.)
3. **Уровень 3** — Синергия (карта, требует 2+ эволюции)

### Пример синергии
```js
{
  id: 'blooddance',
  n: 'Кровава тризна',
  req: () => synReady('sword', 'poison'),
  apply: () => {
    P.dmgMul += 0.25;
    poison.lvl++;
    P.synBloodDance = 1;
  }
}
```

### Функция `synReady()`
```js
function synReady(...ks) {
  for (const k of ks) if (!_synHas(k)) return false;
  if (!ks.some(_synEvo)) return false;           // минимум 1 эволюция
  return ks.every(k => _synEvo(k) || _synLvl(k) >= 3);
}
```

**Сильная сторона**: синергии появляются **сами**, когда условия выполнены.

## 6. Глобальное состояние (главная боль)

**Файл**: `state/run-state.js`

### Проблема
```js
let P = { x:1000, y:1000, hp:100, ... }; // 40+ полей
let enemies = [], slashes = [], bolts = [];
let poison = {on:false, lvl:1}, thorn = {...}, frost = {...};
let hasOrbit = false, orbCount = 0;
let time = 0, kills = 0, gold = 0, level = 1;
// ... ещё ~30 переменных
```

### Последствия
- Нет инкапсуляции
- Сложно тестировать
- Легко сломать при рефакторинге
- `resetRun()` должен знать про все переменные

### Рекомендация
Создать класс `GameState` с методами `reset()`, `serialize()`, `deserialize()`.
