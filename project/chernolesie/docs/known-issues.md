# Известные проблемы

Что осталось нерешённым после ревью v7.8. Исправленное — в конце файла.

## 1. Шестнадцать кадров Воина не загружаются

**Файл:** `src/game/data/hero-warrior-v674.orphan.js`
**В оригинале:** строки 1902–1924

Блок `v6.74: НОВЫЙ ВОИН — единый макет 4x4` лежит **между** `</script>`
(строка 1901) и `<script>` (строка 1925). То есть вне тегов скрипта — браузер
считает его текстом, а не кодом.

Следствие: 16 перерисованных кадров Воина (`Heroes/Warrior_norm/f_01…f_16`)
никогда не подменяют старые. Игра рисует Воина кадрами из
`sprite-atlas.js`, а новый арт лежит мёртвым грузом.

Проверить: в консоли на живой игре
```js
EMB['Heroes/Warrior_norm/f_01.png'].length
```
Если совпадает с длиной в `sprite-atlas.js`, а не в orphan-файле — новый арт не применился.

**Как включить:** добавить файл в список скриптов сборки — в
`src/build.manifest.json` он уже есть как `part`, но окружён литералами так,
что попадает вне тега. Достаточно перенести его внутрь второго `<script>`,
то есть поставить перед `game/boot/00-build-log.js`.
После этого прод-сборка перестанет совпадать с эталоном — это ожидаемо
и правильно, но **проверь Воина визуально**: старый и новый арт могут
отличаться по размеру кадра и точке опоры.

## 2. `ysdk.getLeaderboards()` устарел

**Файл:** `src/game/platform/yandex-games.js`

SDK Яндекса пишет в консоль:
```
ysdk.getLeaderboards() is deprecated. Please, use ysdk.leaderboards.
```
Сейчас работает, но метод помечен устаревшим. Замена — `ysdk.leaderboards`
с тем же набором вызовов. Ошибка не фатальна: код обёрнут в `catch`,
без лидербордов игра работает.

## 3. Порядок разделов нельзя менять произвольно

Игра исполняется в одном общем скоупе. Часть кода **вычисляет** имена функций
на этапе загрузки, а не при вызове:

```js
// src/game/core/input.js:39
document.getElementById('tbtnPause').addEventListener('click', togglePause);
```

`togglePause` объявлен в `src/game/ui/overlays.js`, который грузится позже.
В одном скрипте это работает благодаря подъёму объявлений. Если разложить
модули по отдельным `<script src>` — падает с `ReferenceError`.

Именно поэтому dev-сборка склеивает модули в те же три скрипта, что были в
оригинале, а раздельность возвращает source map. Не пытайся «улучшить» это,
раздав каждому модулю свой тег, — сначала придётся вынести все такие
привязки в отложенную инициализацию.

Известные точки с той же проблемой: `togglePause`, `useSpecial`, `openJournal`.

## 4. Мёртвый код, помеченный автором

В комментариях по коду встречается «отключено» / «удалён» — эти вещи
объявлены, но не работают. Не баги, а осознанные отключения:

- `motes`, `fireflies`, `leaves`, `fogMist` — атмосферные слои выключены (v5.11, v5.14.1)
- `#wakeup` — элемент удалён, стили остались
- `SAVE_VERSION` — не используется до появления миграции сохранений

## 5. Мелочи, найденные ревью и оставленные как есть

- **Баннеры прошлого забега.** `_btTmr` (ui/juice.js), `_surgeTmr` (systems/surges.js),
  `_evoTmr` (systems/evolutions.js), `_achTimeout` (systems/achievements.js) не
  снимаются в `resetRun`. Титр или плашка достижения от прошлого забега может
  всплыть в первые секунды нового. Живёт ≤2.4 с. Туториальные таймеры автор
  снимает явно — эти забыл.
- **Потолок HP врагов пробивается.** `enemyHpMul` в systems/director.js считает
  `Math.min(BALANCE.hpMax, m) * directorHpMul() * diff` — ограничение применено до
  множителей, так что фактический предел выше заявленного до ×1.7.
- **`e.stun` — мёртвый код.** Нигде не выставляется больше нуля (только обнуляется
  в damage.js:33 и clearEnemy), поэтому ветки `if(e.stun>0)` в entities/enemy-ai.js
  недостижимы. Остаток вырезанного в v7.2 локального стана.

## 6. `chernolesie_v7 (2).html` в корне — эталон, а не рабочий файл

Он оставлен как точка сверки: `npm run verify` доказывает, что сборка из
исходников даёт ровно его. Как только ты внесёшь первую правку в `src/`,
сверка начнёт показывать расхождение — это нормально. Файл можно будет
удалить, когда убедишься, что новая сборка играется как надо.

# Исправлено в v7.8

Найдено полным ревью, починено и проверено замером в браузере.

### Сетка разведения врагов росла без предела
`core/loop.js`, `entities/enemies-tick.js`, `systems/run-reset.js`

`_sepGrid` заводила ячейку на каждые посещённые 48 px мира и не удаляла её
никогда — ни между шагами физики, ни между забегами. Очистка перед заполнением
обходит все ключи, поэтому её цена росла линейно с пройденным путём и копилась
через всю сессию.

Замер до: 20 000 px пути → **10 252 ячейки, все пустые**, 0.24 мс на обход,
~44 мс в секунду впустую на десктопе (60 кадров × 3 шага физики). На телефоне
кратно хуже — это и была просадка к концу забега.

Замер после: **80 ячеек**, стоимость обхода ниже порога измерения. Пустые ячейки
выбрасываются из Map, их массивы уходят в пул — пересоздания массивов, которого
избегала правка v6.74, по-прежнему нет.

### Каждый забег оставлял вечно работающий источник шума
`audio/ambient-music.js`

`stopAmbient()` уводил громкость в ноль, но не останавливал зацикленный
`BufferSource` ветра — ссылки на него не оставалось, она была локальной `const`
внутри `startAmbient()`. Следующий забег заводил ещё один. Десять забегов —
десять живых генераторов шума в аудиографе.

Проверено: после правки `onended` у источника срабатывает, то есть он реально
останавливается, а не просто теряет ссылку.

### Треск веток и птицы умирали навсегда при первой паузе
`audio/ambient-music.js`

Выход по `paused`/`over` стоял **до** перепланирования таймера, поэтому цепочка
обрывалась насовсем. Воскресить было нечем: `_ambientRunning` оставался `true`,
и `startAmbient()` выходил на первой строке.

`showCards()` ставит `paused=true` — значит первый же левелап (интервал треска
0.8–3.3 с) глушил оба слоя до конца сессии, и весь забег лес звучал одним ровным
ветром. Теперь на паузе пропускается только звук, цепочка живёт.

Заодно: `_ambientTimers` копил ~1200 мёртвых id за забег — заменён на по одному
id на цепочку.
